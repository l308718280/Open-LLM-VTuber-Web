# 实施路线、验收与待决策事项

## 1. 分阶段实现，不一次接齐所有供应商

本文件是后续实施计划，不代表 Java 服务、测试或性能验证已经完成。协议字段以 [`backend.md`](../backend.md) 为准，状态策略以 [`03-session-lifecycle.md`](03-session-lifecycle.md) 为准。

| 阶段 | 最小交付 | 通过条件 |
| --- | --- | --- |
| P0：协议闭环 | Java 启动、WS 路由、默认角色与资源、历史持久化、固定纯文字回复 | 真实前端可初始化、新建/切换历史、发送文字、看到聊天回复并回到空闲；未启用能力明确报错 |
| P1：LLM | 供应商适配、上下文预算、分句增量、取消与超时 | 连续多轮无重复拼接；取消、失败、断线后资源回收且无旧轮结果继续发送 |
| P2：语音 | 核实采样格式、ASR、分句 WAV TTS、文字降级 | 语音转录只出现一次；独立音频可播放；乱序合成有序输出；失败不永久卡住 |
| P3：视觉 | 图片校验、视觉模型、权限与隐私策略 | 摄像头/屏幕图片正确进入当前轮；无图、坏图和超限可控；不串用户 |
| P4：工具与群组 | 工具状态、隔离浏览器、授权代理、群组策略 | 状态更新、撤销访问、转发防循环和权限校验通过；不支持的能力不伪装成功 |
| P5：生产加固 | 登录、限流、容量、监控、代理、备份与停机 | 完成安全、故障及目标负载验收，记录剩余前端限制 |

安全校验、大小限制和取消机制从 P0 开始；P5 是生产验证，不意味着前面可以公网无鉴权运行。若先只需要聊天助手，可在 P2 停止扩展，工具和群组仍明确返回不支持。

## 2. 协议与数据验收矩阵

- 对 17 类入站建立有效、缺字段、字段类型错误、超长、未授权用例；未知类型明确拒绝。宽泛前端类型不能代替逐消息契约。
- 对 20 类出站建立精确字段、布尔值、空数组、空音频、可空历史摘要与工具状态样例。原生 JSON 顶层结构不增加包装，混合命名不被全局转换。
- 建连后列表响应先于新建成功；角色切换只产生一次新建历史；删除失败纠正列表时保持当前历史在首项。
- 文字输入不重复回显成第二条用户消息；语音转录只追加一次。纯文字回复进入聊天记录，而非仅有字幕。
- 分段增量拼接得到完整且不重复的回复；同名角色、不同头像、工具消息穿插、强制新气泡均验证真实显示效果。
- 历史按稳定服务端序号输出；时间统一时区格式；空历史、包含工具状态、部分生成后取消、超长历史截断及数据库重启后读取均有明确定义。
- 多用户不能凭猜测历史 ID 读取、删除或生成；同用户多标签页访问同一历史时，生成互斥/拒绝策略必须稳定且不会覆盖对方数据。

建议先用受控 ASR/LLM/TTS 替身生成确定性结果、乱序完成、超时及错误，再接真实供应商。单元测试覆盖 DTO、状态转换和分句；集成测试覆盖真实 WS、事务、授权和资源；最终以现有浏览器及 Electron 页面联调，不能只用脚本收到 JSON 就认定兼容。

## 3. 时序、取消与前端兼容验收

| 场景 | 应验证的结果 |
| --- | --- |
| 开始、强制新气泡、首段紧邻发送 | React 状态和闭包更新后第一段仍显示正确，不因上一轮中断状态被丢弃 |
| 最后一段、合成完成、控制结束 | 队列播完后空闲；合成标志及时可见；不重复结尾，不依赖固定 sleep 掩盖竞态 |
| 独立结束与控制结束 | 分别验证其行为，不能因消息名字相似就混用；备用策略有明确适用条件 |
| 空音频、多段纯文字、空回复 | 聊天显示正确，无无限等待；空回复有明确提示或正常收尾 |
| 无 Live2D、播放失败、自动播放被拦截 | 任务能终止，后端不把回执当成功播放的证据，不无限占用轮次 |
| 回执缺失、重复、迟到 | 不重新生成、不重复落库、不把旧回执直接归入新轮 |
| 上传中断、重复结束、结束缺失 | 缓冲封存至多一次；超时回收；残留分片不混进新语音 |
| 生成/合成/播放期间中断 | 旧轮失效、未发事件清理、资源取消；终态更新只有一次 |
| 前端清队列后旧任务完成 | 检查旧 Promise、结束控制和回执是否影响新轮；记录需要前端代次隔离的缺陷 |
| 切换角色、历史、新建、断线 | 先使旧轮失效；新结果只进入正确绑定；旧连接结果不续发给新连接 |
| 自动主动说话与用户输入竞争 | 用户优先；冷却、空闲检查原子执行，不产生两个活跃轮次 |
| 客户端读取缓慢或停止读取 | 事件和字节队列有界；按策略超时关闭并取消任务，不耗尽全局内存 |

当前清队列不会真正取消已启动 Promise，见 [`task-queue.ts`](../../src/renderer/src/utils/task-queue.ts:23)。后端能抑制未发送的旧结果，不能撤回已发送内容，也不能单独修复前端旧回调。发现相关失败应列为兼容限制或安排前端修复，不能用服务端内部轮次 ID 宣称已经完全隔离。

## 4. 资源、安全与故障验收

- 背景、头像、模型及所有子资源逐项加载；验证相对路径、不同基础地址、跨域纹理、正确 MIME、缓存更新和缺失资源的 404。
- 在实际 HTTPS 页面、反向代理和 Electron 包中验证 WSS、Origin、Cookie、浏览器嵌入、第三方 Cookie 限制与音频权限。
- 测试路径穿越、资源根逃逸、无效 Base64、超像素图片、过长音频、恶意 JSON 和高频连接；拒绝不能引发进程崩溃或持续增长的内存。
- 测试历史/群组/浏览器会话越权、撤销登录后旧 WS、过期调试链接、非法 Origin、SSRF 重定向和私网目标；工具不能读取其他用户文件和登录态。
- 注入供应商限流、超时、半途中断、数据库不可用、代理断线、节点退出及浏览器进程崩溃；用户收到可理解的结果，轮次不遗留永久运行状态。
- 核验日志、链路追踪和错误上报不包含密钥、图片、音频、会话票据和敏感聊天；备份恢复后私有数据归属不变。

## 5. 性能目标的制定方式

先确定并发在线连接、同时生成数、语音时长、图片大小、历史长度和目标供应商，再设定首字/首音延迟、取消耗时及内存预算。分别记录中位数、高分位、失败率和队列峰值，并注明硬件、网络与模型版本。

服务端首音是开始发送首个可播放 WAV 的时间，用户首音是实际播放开始，两者必须分开；旧播放开始提示不能作为准确用户首音。压测同时包含慢客户端和取消风暴，不只测正常短文本。当前没有压测数据，不能将任何示例容量或代码定时器当作 SLA。

## 6. 开工前需确认的决策

1. 产品范围：仅本地单用户还是公网多人；是否首版必须包含视觉、浏览器工具和群组。
2. 技术约束：Java/Spring Boot 具体版本、数据库、部署平台、CPU/内存和是否允许转码子进程；现有 Maven 文件只是占位，不是可运行后端。
3. 供应商：ASR/LLM/TTS/视觉接口、模型、地域、数据保留、限流、价格及取消能力；音频有效采样参数必须实测确认。
4. 数据策略：历史是否跨角色共享、取消后的部分回复如何保存、图片音频留存期限、群组共享范围、用户导出与删除。
5. 并发策略：同历史多连接是否拒绝、群主离开规则、主动说话冷却、工具副作用确认和费用归属。
6. 兼容边界：是否允许前端增加请求/轮次/音频序号、上传格式描述、登录流程、明确播放结果和恢复游标；没有这些字段时接受哪些限制。

本轮文档验收仅检查覆盖范围、文件内容及引用完整性；上述业务与运行测试必须在后端实现后执行。建议以 [`00-overview.md`](00-overview.md) 作为方案入口，以本节决策和每阶段通过条件作为实施评审清单。
