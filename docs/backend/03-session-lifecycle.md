# 会话生命周期、时序与取消

## 1. 状态分层

以下时序是新 Java 后端的建议策略，并非已验证的旧后端行为。协议依据见 [`backend.md`](../backend.md)，前端分发实现见 [`websocket-handler.tsx`](../../src/renderer/src/services/websocket-handler.tsx:59)。

不要用一个“是否正在说话”布尔值涵盖全部状态。建议分别维护：连接存活和代次、角色和历史绑定版本、音频收集中状态、对话轮次状态、生成完成状态、客户端播放完成提示。轮次终态至少区分成功、失败、取消；播放等待应有截止时间，不阻塞数据库事务或连接状态通道。

连接内单轮运行不等于一个用户只有一个连接。多个标签页可操作同一历史，需按历史增加并发写入约束：建议首版拒绝同一历史的第二个活跃生成，或显式排队并告知用户，不能用各连接独立锁来假装解决共享历史写入。

## 2. 建连与初始化

1. 完成身份与 Origin 校验，分配新的临时连接 ID，绑定默认角色，建立有界收发通道。
2. 推送当前角色和完整模型信息。不能等待角色文件列表请求才确定当前角色。
3. 按前端发送顺序处理背景、角色配置、历史列表、新建历史请求。
4. 历史列表响应先于新建历史成功响应发出；新建成功后原子绑定服务端当前历史。
5. 初始化完成前到达的输入，建议明确拒绝并收尾，不默默写入任意默认历史。

连接重建后的前端会重新初始化并请求新建历史，不应将它当作恢复旧轮次。历史列表和角色资源可缓存，但每次响应必须按身份及当前角色过滤。

## 3. 文字、语音与主动说话

### 3.1 文字的正常路径

1. 校验输入、图片、身份和历史归属，处理忙时策略，建立内部轮次并保存用户消息。
2. 发 control 开始指令，然后启动 LLM；前端已本地追加文字，不重复发转录事件。
3. 将文本按句或受限长度分段，TTS 可有限并发但按句序下发 audio；展示文本必须为增量。
4. 纯文字模式同样发送 audio，音频为空字符串，展示文本包含本段文字、名称和头像；可另发 full-text 更新字幕。
5. 最后一段发送完成后，执行第 4 节统一收尾。

不要依赖同一批事件触发 React 状态立即同步。特别是开始指令、强制另起消息和首段文本连续到达的情况，需要真实前端验收，而不只是检查 WS 字节顺序。

### 3.2 语音路径

首片建立受限音频缓冲，后续片按连接顺序追加；结束消息将缓冲和图片封存为一次输入，然后立即解除该缓冲的可写状态。ASR 成功后发送一次转录事件，再进入模型链；空转录可提示未识别到内容并正常收尾。

开始指令应在确认接受语音输入后、模型输出前发出；ASR 阶段同样受截止时间和取消令牌约束。缺失结束消息则按收集超时清理；重复结束且无缓冲不重复调用 ASR。新采集开始、角色或历史切换、断线时清理旧缓冲。

### 3.3 主动说话与忙时策略

主动说话不伪造用户文字，不默认转录回显。自动触发只在空闲、满足冷却且权限允许时接受；手动触发仍受配额约束。主动连续回复需要显式设置新气泡边界。

用户新输入在忙时建议采用“取消旧轮后接受新轮”，而非同时生成。取消和新轮开始必须经过同一串行状态通道；自动主动说话不能抢占正在进行的用户对话。无请求 ID 时，拒绝某次输入的错误提示可能影响用户理解，应明确提示原因，避免让错误收尾误终止另一个轮次。

## 4. 生成结束与播放结束

推荐先联调以下单一正常收尾路径：最后一段 audio → backend-synth-complete → control 的结束指令。结束控制被加入播放队列，因此不必等播放回执才发送它；否则容易构成等待循环。服务端可以记录播放等待，但应在超时后释放资源。

独立 conversation-chain-end 仅在前端队列为空时尝试恢复空闲，适合经验证的无队列或回执后兜底分支，不作为上述结束控制的等价替换，也不盲目向所有轮次补发。它不会执行结束控制里的自动开麦逻辑。

播放回执是在合成完成标志和队列完成条件下产生，并不证明成功播放。依据：[`use-audio-task.ts`](../../src/renderer/src/hooks/utils/use-audio-task.ts:229)。无音频、模型未加载、浏览器拒绝播放均须验证；服务端不能无限等待这个回执。

error 只提示错误。轮次在 ASR、LLM 或 TTS 阶段失败时，应先停止继续生产事件，再对该仍活跃轮次发错误及适用的收尾；若前端已开始等待而没有任何音频，也不能只发送错误。TTS 部分失败可将尚未展示的本段文字降级为空音频消息，不重复已展示片段。

## 5. 中断、迟到结果与状态切换

1. 在状态通道中先将旧轮次标记失效，再清除待发旧事件；取消外部流、TTS、ASR 和工具等待。
2. 所有异步结果附带连接代次、历史和角色版本、轮次与句序；回到状态通道和真正发送前均重新检查有效性。
3. 接到用户中断时不原样回发形成循环。需要服务端主动停止客户端播放时可发独立中断事件；群组转发应限定范围。
4. 保存取消终态与已生成/已发送的有限摘要。客户端累计文本只能作提示，不能据此覆盖数据库原文或断言精确听到哪里。
5. 历史切换、角色切换、新建历史先取消旧轮并清音频收集缓冲，再修改绑定，最后按顺序通知前端。角色切换通知会触发前端新建，不额外自动新建第二份。
6. 断线清理连接资源和群组在线成员，关闭浏览器会话或按短 TTL 回收；不把旧轮输出转给新连接。

前端清队列不等于中止已启动 Promise；其实现还会清除活动任务集合。依据：[`task-queue.ts`](../../src/renderer/src/utils/task-queue.ts:23)。因此旧完成回调、已经发出的结束事件和无轮次回执都可能跨越新轮边界。内部令牌只能阻止尚未发出的消息，严格隔离必须升级前端协议与队列实现。

## 6. 幂等与故障边界

轮次终态使用条件更新，成功、超时和取消竞争只能一个胜出。终态事件由统一收尾入口生成；取消后不得又发成功结束覆盖新状态。连接关闭和取消重复执行应安全。

不要把超时后迟到的播放回执自动归给新轮次。兼容模式下只作非关键遥测或在明确播放等待窗口内谨慎接受，不能据它放行副作用操作。服务重启标记遗留轮次结束，不自动重放浏览器提交、付款或其他有副作用动作。
