# Java 架构与存储方案

## 1. 技术选型建议

以下为建议，不是现有工程配置。

| 层次 | 建议 | 原因与约束 |
| --- | --- | --- |
| 运行时 | Java 21 LTS | 可使用虚拟线程；仍需限制并发、队列和外部连接数 |
| Web | Spring Boot + Spring MVC + 原生 WebSocket | 保持现有 JSON 文本帧；无需 STOMP 消息代理 |
| 序列化 | Jackson，按消息类型注册 DTO | 显式字段映射，避免全局命名策略破坏混合大小写字段 |
| 持久化 | MySQL；JDBC 或 MyBatis 二选一 | 初期关系清晰、事务边界明确；使用迁移工具管理表结构 |
| 外部调用 | 支持流式响应、超时及取消的 HTTP 客户端 | 不把供应商响应直接透传给浏览器 |
| 模型集成 | 自定义轻量适配层，可选 Spring AI | 先满足协议和取消能力，不让集成框架决定传输协议 |
| 静态资源 | 外置只读资源目录，或反向代理资源服务 | 模型与纹理不宜全装入内存，资源独立发布 |
| 多节点 | 暂不引入；扩容时再评估 Redis 和路由 | 共享数据库不能迁移已建立的 WebSocket 与活跃任务 |

准确的 Spring Boot、驱动和集成库版本在初始化工程时选择并锁定，检查 Java 兼容性、维护状态和依赖漏洞；本方案不虚构已验证的版本组合。

## 2. 模块划分

建议先一个部署单元、内部按职责分包，不必立即建立多个 Maven 子模块。若新建独立仓库，前端只更改后端地址；若放同仓库，先规划独立后端目录，不把占位 Maven 配置直接当成启动工程。

| 模块职责 | 输入与输出 | 禁止承担的职责 |
| --- | --- | --- |
| 协议接入 | 握手、JSON 校验、消息路由、事件序列化 | 不直接调用模型并等待完成 |
| 连接管理 | 身份、连接 ID、角色、当前历史、发送队列、关闭清理 | 不用客户端 ID 代替登录身份 |
| 会话与历史 | 归属检查、切换、新建、查询、删除 | 不在数据库事务中等待网络模型调用 |
| 对话编排 | 输入归一化、上下文、工具循环、分句、语音调度、取消 | 不解析供应商专有协议 |
| 能力适配 | ASR、LLM、TTS、视觉、浏览器工具 | 不直接向任意连接发送消息 |
| 配置与资源 | 角色清单、模型信息、背景、头像、资源白名单 | 不接受任意文件路径读取 |
| 群组协调 | 群主权限、成员在线状态、广播和转发去重 | 不隐式共享所有私有历史 |
| 运维支撑 | 限流、指标、脱敏审计、健康检查 | 不记录原始图片、音频和凭据 |

## 3. 并发与背压

- 每个连接设置串行状态通道，保证历史列表、新建、切换及上下文修改有顺序；这里“串行”不代表把长耗时模型任务锁在通道内。
- 长任务在受限执行器中运行，完成或流式事件带内部连接代次、角色版本、历史 ID 和轮次 ID 返回状态通道。出站前再次检查仍属于当前任务。
- 一个连接只有一个实际发送者。工作线程只投递事件，不并发写 WebSocket；设置队列字节数、事件数、发送超时和慢客户端关闭策略。
- 音频输入单独聚合；从收到首片到结束都有总样本数与时间限制。中断控制不应被排在一个长期阻塞的模型调用后面。
- 取消顺序：使轮次失效、丢弃未发送旧事件、取消外部请求、关闭流、释放音频及工具资源。只取消 Java Future 不保证底层网络请求终止。
- TTS 可有限并行，但必须按句序下发。早句失败时必须明确降级或结束，不能无限等待而积压后续句子。
- 虚拟线程不等于无上限：为每个供应商、用户和系统设置并发配额，数据库连接池和 HTTP 连接池另行限制。

## 4. 数据模型建议

表名和字段名在实施时确定，下表描述语义，不是既有数据库结构。

| 实体 | 关键内容 | 索引与一致性 |
| --- | --- | --- |
| 用户 | 服务端用户标识、认证映射、状态 | 外部身份映射唯一 |
| 角色配置 | 稳定角色标识、前端配置文件别名、展示名、模型元数据、供应商配置引用、版本 | 文件别名来自注册清单，不能直接映射任意磁盘路径 |
| 历史会话 | 会话标识、所属用户、角色标识、创建/更新时间、删除状态、版本 | 用户 + 角色 + 更新时间索引；每次读写检查归属 |
| 对话轮次 | 会话、内部轮次 ID、状态、输入来源、开始/结束时间、错误类别 | 一次输入对应一次轮次；终态更新幂等 |
| 消息 | 服务端 ID、会话、轮次、序号、角色、内容、时间、展示名、头像 | 会话 + 序号唯一；时间戳不能代替排序序号 |
| 工具执行 | 工具调用 ID、轮次、名称、状态、脱敏摘要、耗时 | 工具调用 ID 唯一；状态原位更新 |
| 可选群组 | 群组、群主用户、成员及在线连接映射 | 持久成员身份与临时在线连接分离 |

使用 UTC 保存时间，对前端输出 ISO 8601 时间字符串；历史角色必须映射为 [`Message`](../../src/renderer/src/services/websocket-service.tsx:30) 接受的 human/ai，而不是直接输出供应商的 user/assistant。

## 5. 事务和上下文

1. 输入通过校验后，短事务写入用户消息和运行中轮次，提交后才调用模型。
2. 逐句输出按内部序号记录。区分“生成”“发送”“播放开始的提示”三种信息，不把客户端回执当成可信已听完证明。
3. 成功、失败、中断用条件更新进入唯一终态，并维护历史摘要；断线轮次可标记取消或失败，不悄悄续发给新连接。
4. 模型上下文由服务端受控构建：角色指令、最近消息、摘要和本轮图片；限制 token 预算。历史展示不是把供应商原始上下文直接返回。
5. 图片和音频默认只短期驻留处理，不自动永久入库。若需要回放，另行设计用户授权、对象存储、保留期限和删除联动。
6. 服务重启后将遗留运行中轮次恢复为明确终态，不重跑有副作用工具；历史可持久恢复，但旧连接和音频流不能恢复。

## 6. 适配层能力约定

ASR 接收已确认采样参数的音频，返回文本及可选置信信息；LLM 接收受限上下文，产出文本增量或工具调用；TTS 接收完整句子，返回可独立解码 WAV；工具接收经验证参数并返回结构化结果。所有适配必须支持总截止时间、取消、错误归类和用量统计。

供应商重试应只在未对用户产生输出、且调用可安全重放时进行。浏览器点击、表单提交等操作不能因为网络超时就盲目重试。
