# 工具、群组、安全与部署

## 1. 浏览器工具不是一个普通展示链接

已核实：浏览器面板通过 iframe 展示后端下发的调试页面，并允许脚本、同源行为和剪贴板权限，见 [`browser-panel.tsx`](../../src/renderer/src/components/sidebar/browser-panel.tsx:60)。它不是读取用户本机已打开的网页。工具状态及浏览器信息结构见 [`backend.md`](../backend.md:130)。以下为新后端建议。

- 每个用户或任务使用隔离的浏览器上下文，不共用 Cookie、下载目录、登录态和调试端口。不能把任意原始 CDP 端口直接暴露公网。
- 调试页面和它连接的 WebSocket 都必须校验身份、会话归属和有效期；保护 iframe 首页不足以保护调试通道。授权不依赖难猜的会话 ID。
- 建议通过受控代理提供短期访问，注销、会话关闭或到期立即撤销。地址若包含短期票据，应从日志、错误上报和 Referer 中脱敏；不要传长期 API 密钥。
- iframe 的 CSP 嵌入策略、浏览器第三方 Cookie 限制及 HTTPS/WSS 必须实测。不要全局移除安全头；只对授权调试页面开放指定父页面来源。
- 将不可信浏览器内容与主应用隔离到不同源，避免同源脚本结合宽松 sandbox 权限削弱隔离。嵌入权限并不意味着允许页面访问主应用身份。
- 每次工具执行先产生唯一调用标识和运行中状态，成功或失败更新同一条记录；限制步骤数、总时长、下载字节和并发浏览器数量。
- 浏览器点击、提交、发送消息等有副作用动作需要明确用户授权。超时后先查询实际结果，不盲目重试；网页中的指令视为不可信内容，不能覆盖用户目标或绕过权限校验。

断线、中断和切换历史时按策略关闭或短 TTL 保留浏览器，但不能把旧会话无授权绑定到新连接。前端目前没有明确的浏览器视图撤销协议，失效页面应由代理拒绝继续访问；可靠清空旧面板建议后续配合前端实现。

## 2. 群组的权限与转发

前端提供邀请、移除、退群和成员查询，没有完整的被邀请者确认流程。多人部署建议先采用预授权联系人或管理策略，正式“邀请—接受”需扩展前端；不能只知道连接 ID 就把用户强制加入并共享内容。

建议首版明确以下规则：群主可邀请和移除他人，普通成员只能退出自己；群主离开时解散或明确转移，断线移除在线映射；重连得到新连接 ID，不自动继承未验证的群组权限。服务端原子更新后广播状态，不能依赖前端 100 ms 后查询的时机保证一致性。

客户端发来的播放开始提示包含展示文字，不能将其原样当可信群组消息广播。优先从服务端已生成的段落缓存转发，限定来源连接和当前群组；缓存匹配不明确时丢弃，不按客户端提供的名称或头像冒充其他成员。

转发内容要标记为转发，避免接收端再次发送播放开始提示形成循环。但该标记不是认证信息，服务器仍要自行鉴权、去重和限流。回执无段落 ID，严格一次转发不能靠文本比较保证；若需要可靠同步播放，应升级音频标识及回执协议。

群组历史采用独立共享域，不默认复制成员私有历史、摄像头、屏幕或工具登录态。先定义谁能中断谁、是否串行发言、谁承担模型费用；多角色轮流发言还需要轮数和预算上限，避免无限互相触发。

## 3. 身份认证与数据隔离

浏览器 WS 构造当前仅传 URL，见 [`websocket-service.tsx`](../../src/renderer/src/services/websocket-service.tsx:148)。不能假设旧前端能携带自定义 Authorization 请求头。建议同源部署，通过已有登录网关或新增登录流程建立安全 Cookie，并在升级握手校验；当前工程未实现该登录流程，公网版本需补齐。若使用一次性握手票据，也需前端获取票据的配合。

Cookie 使用合适的 Secure、HttpOnly、SameSite 和过期策略；握手严格检查允许的 Origin，防止跨站 WebSocket 劫持。Origin 不等于身份认证，非浏览器客户端可以伪造；CORS 也不能代替 WS 握手授权。登录过期或撤销时主动终止长连接或持续校验会话。

本地单用户 MVP 可只监听回环地址，但依然限制浏览器来源、防止恶意网站连接本地服务。Electron 的实际 Origin 需检查打包与开发环境；不要为了兼容桌面端就无条件允许任意来源或所有空 Origin。

每次历史读取、切换、删除、生成、群组操作、调试页面和私有资源访问都校验所属用户。客户端 ID、历史 ID、配置别名不是权限凭据。密钥只保留服务端环境或秘密管理系统，不放角色清单、模型信息、浏览器 URL、前端包或错误响应中。

## 4. 输入与网络安全

- 角色和资源路径使用白名单及根目录约束，阻止路径穿越、编码变体和符号链接逃逸；数据库操作参数化。
- 服务端访问用户 URL、工具导航、下载和模型返回链接时防 SSRF：只允许必要协议和目标，校验 DNS 解析、每次重定向及最终地址，阻止回环、私网、链路本地和云元数据地址；结合网络出口规则防 DNS 重绑定。
- 不提供任意 shell 或任意文件访问工具。工具参数结构化校验，按用户和任务授予最小权限；第三方页面、模型输出都不能自行授权新的能力。
- 限制 WS 连接数、握手速率、单消息、音频累计、图片解码、上下文 token、工具步骤及供应商用量；区分用户配额和全局资源保护。
- 默认日志只记录消息类型、关联标识、耗时、大小、错误类别，不记录完整聊天、音频、图片、Cookie、票据和浏览器调试地址。现有前端存在完整消息日志，公网前也应评估并脱敏，此处不修改前端。

## 5. 部署、运维与扩容

建议先单实例 Java 服务、关系数据库和只读资源目录。可由同源反向代理同时提供前端、WS 和 HTTP 资源；路径与前端设置对齐，不要求维持默认端口。供应商 URL、超时、资源根目录、允许来源和配额均外置配置，启动时校验必需配置但不输出秘密。

代理必须支持 WebSocket Upgrade，正确设置闲置与上游超时；长模型调用不能被普通短 HTTP 超时切断。可使用协议级 Ping/Pong 检测死连接，不自行发前端未处理的业务心跳消息。健康检查使用独立管理路径，不能以 WebSocket 是否有会话判断健康。

存活检查判断进程是否失去服务能力；就绪检查判断是否能接入新请求，避免某个可选供应商瞬时失败导致所有实例反复重启。设置 JVM 与容器内存余量、线程/连接池上限、只读运行权限，资源和数据库备份独立于临时容器。

优雅停机顺序：停止接收新连接和轮次，等待有界时间，取消剩余模型与工具任务，写入轮次终态，关闭连接并释放浏览器及临时资源。重启不自动重放副作用工具，数据库迁移与应用版本必须可兼容部署和回滚。

监控至少包括在线连接、活跃轮次、ASR/LLM/TTS 耗时与错误、首字/首音服务端延迟、待发字节、慢连接关闭、取消完成耗时、浏览器会话数、模型用量。关联标识用于日志追踪，不作为指标标签造成无限基数；客户端真实播放延迟需独立采集，不能拿服务端发送时间替代。

扩容前再设计会话路由、跨节点群组广播、连接所有权、分布式配额和历史级生成互斥。粘性会话只能帮助路由，共享数据库或 Redis 不能迁移活跃 WebSocket、Java 任务和浏览器上下文；节点失效默认取消旧轮并让客户端重新初始化。
