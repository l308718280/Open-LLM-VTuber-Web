## Context

本次将旧后端客户端改为 Harness 的轻量展示与采集端。旧协议虽只有一个 WebSocket 地址，却包含背景、角色、历史、群组、语音及播放控制等多类消息；文字和表情还被绑定在音频队列内。仅隐藏按钮无法解除这些依赖。范围以 [proposal.md](proposal.md) 为准。

Harness 内部管理记忆、提示词、模型与工具。前端不复刻这些能力，也不以删除历史管理推导出后端无记忆。已有六项主规约是静态现状基线；本变更通过增量规约明确替换或移除相关要求，未修改的点击、拖动和缩放行为保持原状。

## Goals / Non-Goals

**Goals:**
- 单 POST 图文流完成文字问答、截图问答和主动屏幕观察。
- 请求、截图和模型异步工作具有明确生命周期；文字不等待模型或音频。
- 本地资源支持离线展示；浏览器与 Electron 窗口/桌宠继续可用。
- 删除旧协议及无用功能的 UI、Provider、状态、设置、依赖和构建资源。

**Non-Goals:**
- 不实现 Harness 服务、记忆策略、模型调用或服务端工具。
- 不实现历史管理、音视频端到端、服务端主动调用本机工具或协议双栈。
- 不承诺截图理解效果或性能收益，不重写无关 SDK 交互与窗口管理。

## Decisions

### 1. 一个生成入口，使用 fetch 读取 SSE 响应

采用可配置的完整 HTTP(S) 生成地址，建议路由 POST /api/chat；请求为 JSON，响应为 text/event-stream。路径是本次建议契约，不表示已有后端实现。拒绝保留旧 WebSocket 双栈；不采用原生 EventSource，因为需要 POST 正文和请求取消。

请求字段：协议版本 version=1；随机不透明 session_id；每次操作唯一 request_id；trigger 为 user、manual-observation 或 auto-observation；可选 text；images 数组。每张图片包含 source（screen/camera）、mime_type=image/jpeg、data（Data URL）。只提交本次输入；不提交完整聊天历史、记忆、系统提示词或工具定义。user 至少包含非空文字或一张图片；两种观察请求至少包含一张屏幕图片且不含摄像头图片。

会话 ID 在页面生命周期内用安全随机 UUID 生成，在首次请求及后续请求中复用，后端通过 accepted 事件确认归属。刷新或切换服务地址创建新会话，不自动恢复旧聊天；会话 ID 不是鉴权凭证。长时记忆的用户归属由 Harness 鉴权处理，不绑定前端临时会话 ID。该方式避免首次请求在会话确认前被取消时重复创建难以关联的会话。

事件使用 SSE 的 event 字段表示类型，data 为 JSON，携带 version、session_id、request_id、严格递增 seq（从1连续计数）：
- accepted：第一条事件，确认请求与会话。业务内容不能先于确认。
- text-delta：delta 为字符串，按顺序追加到本轮唯一回复及字幕。
- status：仅允许 queued、thinking、tool-running 等展示枚举与经过限制的公开标签，不携带内部推理、工具参数或结果原文。
- expression / motion：可选本地白名单语义键，不接受远程资源地址或任意命令。
- heartbeat：保活事件，不展示为对话。
- done：终态，outcome 为 replied 或 silent。silent 仅适用于未输出文字的自动观察；不创建空回复或修改上一条字幕。
- error：终态，稳定错误码和可展示消息；前端不直接显示服务端堆栈。

增量 UTF-8 解码和 SSE 组帧必须支持跨网络块的中文、CRLF、空行、多行 data、注释及一次收到多个事件。验证 HTTP 状态、媒体类型、JSON、标识和序号；相同或更小序号忽略，跳号、无 accepted 的业务事件或当前请求的会话错配视为协议错误。未知可选事件消费序号后忽略。终态只结算一次，后续事件无效；无终态断流视为失败而非成功。单事件/未完成帧缓冲上限1 MiB，回复累计上限1 MiB，超限中止，避免不受限内存增长。

收到首事件前超时30秒，事件空闲超时90秒，单请求总时长上限10分钟；heartbeat 只重置空闲计时。非2xx、超时、解析错误、断网均保留已显示的部分文字并标记失败，不自动重放 POST。重新尝试由用户发起新 request_id，避免工具重复执行。Harness 对重复 request_id 去重并对同一会话串行处理；取消未及时生效时可返回 busy，前端不无限重试。

### 2. 生命周期协调器统一仲裁所有提交入口

以一个协调器拥有活动请求、AbortController、递增 generation、截图令牌和临时对话。阶段为 idle、capturing、requesting、streaming；终态为completed、cancelled、failed，结算后允许下一轮。模型加载状态独立，不能阻塞聊天。

用户提交时同步取得准备锁并固定草稿版本与采集来源；重复点击/回车在准备阶段忽略。已有网络请求时用户新提交可先取消旧轮，再开始新轮；编辑本身不取消回复。仅成功启动本次请求后清空仍与快照相同的草稿，新编辑内容不清空。准备失败保留草稿并提示；发送失败保留失败消息供手动重试。附图失败不得默默降级为纯文字；用户可明确选择不附图重发。

取消先增加 generation、标记本轮失效，再中止网络/读流、清理计时器及缓冲。无法物理取消的抓帧或模型回调在完成后核对令牌，过期结果释放而不发送、不写 UI。清理旧请求必须核对请求身份，不能把新请求改回空闲。组件卸载、服务地址变化也执行同样清理。

前端断开请求只保证本地立即停止消费；Harness 及代理必须支持断开传播，并尽力取消模型和可取消工具。已完成工具副作用不可撤销，不能在 UI 宣称事务回滚。取消不增加第二个业务 URL；如果部署链路无法传播取消，单入口契约需在联调时重新评估，不能用本地 Abort 假装后端已停。

### 3. 主动观察是显式授权后的有界调度

自动观察默认关闭且开启状态不持久化，每次页面加载均需用户重新开启。只能使用用户已明确授权且仍存活的屏幕流；开启自动观察本身不弹出隐式采集请求。手动观察同样只采屏幕，不夹带摄像头。UI 显示采集来源、自动观察状态、最近结果以及停止共享/停止自动观察入口。

默认每30秒检查一次，间隔允许10至300秒；两次自动请求启动至少相隔30秒。正在截图/请求、用户正在组合输入或编辑后2秒内、页面隐藏时跳过，不排队补发。用户请求可抢占自动轮；自动轮不能抢占用户轮。浏览器隐藏或 Electron 隐藏均暂停调度，重新可见后重新计时；不新增全局键鼠监听。

变化检测在本地将屏幕帧缩为64×36灰度图，以平均绝对差除以255计算差异，默认阈值0.03，设置范围0.01至1；首次采样可发送，后续与最近一次成功终结（含 silent）的自动请求帧比较。尺寸/屏幕源变化清基线；取消和失败不更新基线。比较帧只保存在内存。变化阈值是可调策略，不是语义理解或隐私过滤。

停止自动观察取消自动计时、在途自动抓帧与自动请求，不影响用户文字请求；停止共享/系统撤销则同时释放屏幕轨道并使观察工作失效。失败不密集重试，连续3次自动失败关闭自动观察并提示，用户重新开启后恢复。Harness 可 silent 完成且自行决定记忆写入；前端不承诺截图永不进入后端记忆。

### 4. 图片、授权和网络隐私边界

保留手动可选主摄像头以及独立背景摄像头；默认关闭，仅明确用户操作启动，背景摄像头从不上传。文字提交可附用户选择且已开启的主摄像头/屏幕，每种来源最多一张；自动与手动观察限定一张屏幕图。默认 JPEG 质量0.8、最长边1280；允许质量0.1至1、最长边320至2048，旧0值迁移为1280。每张编码后原始字节上限2 MiB，总图片原始字节上限4 MiB，请求序列化正文上限6 MiB，超限提示调整而非静默截断。

将捕获器构造、抓帧、Canvas、编码与存储读取都放入异常边界；对不支持 ImageCapture 的环境使用已就绪视频元素加 Canvas 的回退。启动互斥、停止/卸载释放所有轨道、外部 ended 同步状态、迟到启动释放返回流；位图 finally 关闭。设备启动不是设置预览，不因刷新或取消设置重新请求权限。

不记录或持久化截图正文、完整请求/响应、聊天内容或工具敏感信息。删除旧截图日志；仅保留不含正文的请求 ID、阶段、耗时和安全错误码。界面说明图片会发送至当前配置服务。生产远端使用 HTTPS，本机开发允许 loopback HTTP；混合内容限制不通过关闭浏览器安全策略绕过。鉴权采用部署侧短期身份或安全会话，禁止将 Harness/模型长效密钥写入静态包或设置存储。CORS、CSP、跨域凭证与 Electron 来源允许列表由双方部署对齐，不使用任意来源开放凭证。

### 5. 本地资源清单及无音频模型展示

使用 renderer 公共资源目录中的内置清单记录稳定模型 ID、显示名、头像、模型相对入口、布局和有效表情/动作映射；通过应用基础地址解析资源，不拼业务后端地址。只持久化模型 ID 与有限有效布局偏好，启动从清单恢复；配置尺度采用单一标准，重复设置不再次乘2。背景可先用可发布的本地图片或纯色，离线也显示。

模型来源是用户提供目录中的 mao_pro、shizuku；实施前阅读其 ReadMe 与分发条款。仅在允许发布时复制完整 runtime 及必要许可，保持 model3 引用关系；不引用用户电脑绝对路径。两模型均没有 Talk 组，shizuku 未声明 Expressions：映射必须基于实际清单校验，不假设这些资源存在。无对应表情/动作时忽略提示并继续文字；不能让未知键触发资源下载。

重载取消旧延时和异步应用，释放旧模型；可选动作加载失败也推进完成计数，必要模型/纹理失败提供错误状态和重试，不阻塞文字。文字流直接驱动回复/字幕，合法展示事件通过独立适配器驱动模型；恢复默认表情允许有效默认、首个表情、无操作三级回退。移除应用音频播放、口型入口和 PCM 资源链，保留 Cubism Core、通用动作/参数 SDK 与非音频调试功能。

### 6. 壳层裁剪与设置迁移

保留模式、主题、语言、窗口/桌宠、Live2D、字幕、临时对话、媒体面板与设置。以请求状态替换 WebSocket 连接状态；离线模型展示不需要角色、历史或客户端 ID 初始化。

删除群组及历史管理组件/Provider/协议路由，删除麦克风/VAD/ASR、播放与回执，删除远端角色/背景选择、旧 WebSocket 服务和工具浏览器自动打开链。Electron 浏览器相关 IPC 仅在确认无其余用途后移除；不扩大为窗口控制重写。新的状态组合为本地偏好、媒体、Live2D、Harness 会话、观察调度和字幕，替换依赖旧协议的 Provider，而不是把旧 Provider 留作空壳。

设置采用一个已提交状态与每次打开的新草稿；保存校验后提交，取消、叉号、遮罩、Escape 全部丢弃草稿。模型/背景可提供显式预览，但取消必须恢复本地显示且不启动设备。持久化仅白名单本地偏好；迁移失效的语音、群组、历史、旧地址与远端模型缓存，禁止清空整个站点存储。存储异常回退内存并提示，不阻塞输入。服务地址保存成功时取消在途工作、清临时对话、生成新会话；不把旧内容发送给新服务。

## Risks / Trade-offs

- 单向 POST 不支持服务端主动索取新的本机素材 → 本轮客户端先采图；未来本机工具另做授权及双向协议设计。
- 代理缓冲/断线传播和后端幂等尚未验证 → 联调验证首事件、心跳、取消与同会话并发，未达标不得宣称交付。
- 屏幕可能含敏感数据，变化过滤不能识别秘密 → 显式授权、可见停止、最小采样及日志脱敏；服务端留存政策需确认。
- 内置模型增大包体且有分发约束 → 先审许可再复制，记录资源体积，不推导运行性能。
- 旧主规约含静态证据与风险章节 → 同步时保留历史说明但明确它们不是新实现证据，不把已删除能力当验收目标。

## Migration Plan

先确认契约与资源许可，建立可控模拟流验证解析与协调器；再接入本地资源、文字与截图，最后迁移观察调度并删除旧协议/功能链。同步清理两套 Vite 中 VAD、ONNX、worklet 复制及无用依赖，但保留 Cubism Core。更新锁文件时检查其他依赖引用。

按顺序执行类型检查、只读 ESLint、Web 构建、Electron 构建和解包验证；再做浏览器/桌宠离线展示、双模型切换、授权撤销、慢截图、取消竞态、断流、静默和代理联调。现有 lint 脚本带 --fix，验收使用直接不带 --fix 的 ESLint。当前没有测试脚本，先选择能运行的轻量测试入口，不把不存在的测试命令写成已验证。

前后端按协议版本协同发布；不在同包保留双栈。回退通过切换到旧版本制品及配套旧后端，不能仅切换地址。设置迁移不删除无关偏好，必要旧版本回退重新配置，不备份聊天或截图。规划阶段不复制模型、不删除源码、不修改主规约。

## Open Questions

- 发布前确认 Harness 实际路径、鉴权/用户身份、CORS/CSP、取消传播及去重保留时长；本设计字段作为联调基线。
- 两个模型的再分发许可与默认模型尚待核验；未获许可不得把复制任务视为完成。
- 服务端图片留存、工具副作用及长期记忆策略由 Harness 负责人确认，前端仅展示真实政策。
